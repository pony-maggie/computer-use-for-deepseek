Invisible Memory Architecture

Computer Use for DeepSeek keeps the visible product simple while a conservative backend memory layer recalls durable context and forgets noisy task detail.

No UI surface - prompt context only

User Task

The user creates a normal run. No memory controls, no extra choices, no exposed recall list.

Run Result

Final answer, structured events, confirmations, failures, and output names become bounded capture inputs.

Memory Service

Recalls up to five relevant memories before execution, then captures zero to three durable summaries after terminal runs.

Remember Preferences, workflows, stable facts, safety boundaries, lessons.
Forget Credentials, raw files, screenshots, DOM dumps, one-off page detail.
Retrieve Keyword and FTS ranking first; vectors can come later.
Constrain Memory informs prompts but never bypasses approval policy.

SQLite Memory Store

A compact `memories` table stores kind, summary, source run, confidence, use count, and optional expiry.

Hidden Agent Context

Relevant summaries are injected into a private Memory Context block before the existing computer-use loop begins.

Safety Boundary

Memory can suggest caution or preference, but SafetyPolicy still decides blocks and confirmations.

Quiet by design The product stays task, sandbox, and results focused.
High signal only Summaries are short enough to read and safe enough to reuse.
Local first Memory lives beside run history in the existing local database.
Auditable source Run events remain the source for debugging; memory is derived context.
